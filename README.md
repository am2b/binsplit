# binsplit - 二进制文件分割与合并工具

一个用 Go 语言编写的跨平台命令行工具，用于将大文件分割为多个小文件，以及将多个分片文件合并为原始文件。支持按百分比分割、按数量等分、按目标大小分割、目录批量处理、并行加速、可选 AES-256-GCM 分片加密。

## 功能特性

- **三种分割方式**
  - 按百分比分割：如 `30,70` 分为两份，`20,40,40` 分为三份；单值自动补全（`40` → 40%+60%）；多值总和不足 100 时自动补全（差 ≤1% 微调末片不增加片数，差 >1% 追加一片，如 `20,50` → 20%+50%+30%）
  - 按数量等分：如 `10` 表示等分为 10 份
  - 按目标分片大小分割：如 `500M` 表示每个分片约 500MB（末片取余量）
- **完整性校验**
  - 分割时记录原始文件和每个分片的 SHA256 到清单文件
  - 合并时自动校验分片完整性，并比对合并后文件的 SHA256

- **可选加密（AES-256-GCM）**
  - 分割时传入 `-password` 或 `-password-file` 即启用加密，不传则完全不加密
  - 密码支持任意字符，长度不限；合并时必须提供正确密码
  - 支持从文本文件读取密码（`-password-file`）
  

- **可选进度条**
  - 分割/合并均支持 `-progress` 开关

- **目录批量处理**
  - 分割：批量分割指定目录下的所有普通文件（自动忽略隐藏文件）
  - 合并：批量合并指定目录下所有符合 `.parts` 命名规范的子目录
- **跨平台**：支持 Windows、macOS、Linux，编译为单一二进制文件
- **并行加速**：利用多核 CPU 并行处理分片，默认使用 CPU 核心数

## 快速开始

### 编译

需要 Go 1.21 或更高版本。

```bash
# 克隆或下载源码后，进入项目目录
cd binsplit

# 编译
go build -o binsplit .

# 交叉编译（例如在 Linux 上编译 Windows 版本）
GOOS=windows GOARCH=amd64 go build -o binsplit.exe .
```

### 基本用法

```bash
# 查看帮助
binsplit help

# 查看版本
binsplit version
```

## 使用指南

### 分割文件

#### 按百分比分割

```bash
# 将 video.mp4 按 30% 和 70% 分为两份
binsplit split -i video.mp4 -p 30,70

# 将 video.mp4 按 20%、40%、40% 分为三份
binsplit split -i video.mp4 -p 20,40
```

#### 按数量等分

```bash
# 将 video.mp4 等分为 10 份
binsplit split -i video.mp4 -n 10
```

#### 按目标分片大小分割

```bash
# 每个分片约 500MB（单位大小写不敏感，末片可能小于目标大小）
binsplit split -i video.mp4 -s 500M
binsplit split -i video.mp4 -s 500MB

# 支持多种单位：K/M/G/T/P，以及 B；不带单位时按字节计
binsplit split -i video.mp4 -s 5G
binsplit split -i video.mp4 -s 100K
```

#### 指定输出目录

```bash
# 分割结果输出到 ./output 目录
binsplit split -i video.mp4 -n 5 -o ./output
```

#### 目录批量分割

```bash
# 批量分割 ./files 目录下的所有普通文件，每个文件等分为 5 份
# 自动忽略以 . 开头的隐藏文件（如 .DS_Store、.gitignore 等）
binsplit split -i ./files -n 5 -o ./output
```

#### 指定并行线程数

```bash
# 使用 8 个并行线程
binsplit split -i video.mp4 -n 10 -j 8
```

### 合并文件

#### 合并单个分割目录

```bash
# 合并 video.mp4.parts 目录中的分片，恢复为原始文件
binsplit merge -i video.mp4.parts
```

#### 指定输出目录

```bash
# 合并后的文件输出到 ./restored 目录
binsplit merge -i video.mp4.parts -o ./restored
```

#### 批量合并

```bash
# 批量合并 ./all_parts 目录下所有符合 .parts 命名规范的子目录
# 自动忽略其他不相关的文件和子目录
binsplit merge -i ./all_parts -o ./restored
```

## 分割后的目录结构

```
video.mp4.parts/
├── video.mp4-ca6c35ae177ba805...-2.txt
├── 3f8k2j9d4n6v7w8x1y2z3a4b5c6d7e8f9a1b2c3d4e5f6g7h8...
├── q5r6s7t8u9v0w1x2y3z4a5b6c7d8e9f0a1b2c3d4e5f6g7h8...
└── ...
```

### 清单文件格式

清单文件名格式：`原始文件名-清单文件SHA256-分片数量.txt`
例如：`video.mp4-ca6c35ae177ba80518ab161b0813dafc54d8f9273fd03e6506af752084345242-2.txt`

文件内容：

```
# binsplit 清单文件 (manifest)

[软件信息]
工具 = binsplit
版本 = 1.0.0

[原始文件信息]
文件名 = video.mp4
文件大小 = 123456789
SHA256 = abc123def456...
分片数量 = 2
创建时间 = 2026-08-22T12:00:00Z
加密 = 是
加密算法 = AES-256-GCM
密钥派生 = scrypt
盐值 = <64位十六进制，随机生成>
scrypt参数 = 32768,8,1

[分片列表]
# 格式: 序号 | 分片文件名 | 分片大小(字节) | 分片SHA256
1 | 3f8k2j9d4n6v7w8x1y2z3a4b5c6d7e8f9... | 37037036 | def456...
2 | q5r6s7t8u9v0w1x2y3z4a5b6c7d8e9f0... | 86419753 | ghi789...
```

## 完整性校验说明

工具在分割和合并过程中执行多重校验：

1. **分割时**：
   - 计算原始文件的 SHA256，记录到清单文件
   - 每个分片边写边算 SHA256，记录到清单文件
   - 校验每个分片写入的字节数是否符合预期

2. **合并时**：
   - 并行校验每个分片的 SHA256 是否与清单中记录的值一致
   - 合并过程中边写边算总 SHA256
   - 合并完成后比对总 SHA256 与清单中的值
   - 校验文件大小是否一致

如果 SHA256 比对失败，工具会报错并提示，不会静默忽略。

## 加密 / 解密

分割时传入 `-password` 即启用分片加密：

```
binsplit split -i secret.mp4 -s 500M -password "我的密码"
binsplit merge -i secret.mp4.parts -password "我的密码"
```

**在命令行传入密码**：
```
# 安全，不括也行（纯字母数字）
binsplit split -i secret.mp4 -s 500M -password abc123

# 必须括（含空格）
binsplit split -i secret.mp4 -s 500M -password "my secret pwd"

# 含双引号本身、$、反引号或\时必须用单引号
binsplit split -i secret.mp4 -s 500M -password '$3cret'

# 含单引号本身时必须用双引号
binsplit split -i secret.mp4 -s 500M -password "it's mine"
```

**从密码文件读取**：多次加密分割/合并时，可以把密码保存在文本文件中，用 `-password-file` 读取：

```
# 密码文件里存一行密码即可（用 echo 或文本编辑器保存）
echo "我的密码" > ./pass.txt
binsplit split -i secret.mp4 -s 500M -password-file ./pass.txt
binsplit merge -i secret.mp4.parts -password-file ./pass.txt
```

**换行符处理（重要）**：程序会**自动剥离密码文件末尾的一个换行序列**——`CRLF(\r\n)`、`LF(\n)`、`CR(\r)` 。文件中间的换行符会保留（支持多行密码）。唯一例外是密码本身以换行结尾——末尾换行会被剥离（这是 openssl、ssh-keygen 等工具的通用做法）。密码文件不能为空、不能超过 64KB，否则明确报错。

**实现细节与安全保障**：

- **算法**：AES-256-GCM（AEAD，加密 + 完整性认证一体）。分片被篡改或密码错误都会在解密阶段直接报错，不会产出坏文件。
- **密钥派生**：scrypt（带随机盐的慢哈希，抵御暴力破解）。每个文件独立随机 32 字节盐值，写入清单。
- **分块流式**：按 1 MiB 分块加解密，内存占用恒定，可处理超大文件；每块独立随机 nonce。
  
  
- **加密分片文件格式**：`魔数 + [nonce(12字节) + 密文块] × N`，可通过魔数快速识别。

**⚠️ 重要提醒（加密的代价）**：

1. **密码丢失 = 数据永久无法恢复**。加密后的分片如果没有密码，任何人都无法解开（包括你本人、包括未来任何版本的软件）。请务必妥善备份密码。
2. **密码经命令行传入会出现在 shell 历史中**。在共享/多用户环境下注意清理，或使用 `history -c` 等保护措施。
3. 加密不防运行中的恶意软件读取；请同时做好系统安全。
4. 请使用强密码（建议 12 位以上、混合字符），弱密码仍可能被暴力破解。

## 进度条

分割或合并时加 `-progress` 即可显示进度条（输出到 stderr，不污染正常输出）：

```
binsplit split -i ./files -s 500M -progress
binsplit merge -i ./files.parts -progress
```

进度条显示百分比与实时速度。**默认关闭**，未开启时不启动任何进度计算或刷新协程，零额外 CPU 开销。

## 常见问题

**Q: 分割后的文件可以单独使用吗？**
A: 不可以。每个分片只是原始文件的一段二进制数据，必须全部合并后才能恢复为原始文件。

**Q: 可以只合并部分分片吗？**
A: 技术上可以，但合并后的文件是不完整的，SHA256 校验会失败。建议始终合并全部分片。

**Q: 按大小分割（-s）时，末片会小于目标大小吗？**
A: 会。`-s 500M` 表示"每个分片最大约 500MB"，前 N-1 片都接近目标大小，最后一片取文件剩余字节（可能明显小于 500MB）。这是标准行为，且能保证所有分片之和精确等于原文件大小。

**Q: 重复分割同一个文件会怎样？**
A: 如果分割目录已存在且非空，工具会拒绝执行并提示你先删除或改名旧目录，避免旧分片混入导致合并出错。

**Q: 批量合并时目录中有其他文件会怎样？**
A: 批量合并时只处理名称以 `.parts` 结尾且包含清单文件的子目录，其他不相关的文件和子目录会被自动忽略。

**Q: 批量分割时目录中有隐藏文件会怎样？**
A: 批量分割时自动忽略以 `.` 开头的隐藏文件（如 `.DS_Store`、`.gitignore` 等），只处理普通文件。

**Q: 支持多大的文件？**
A: 理论上没有大小限制。工具使用流式读取和写入，不会一次性将整个文件加载到内存中，可以处理几十 GB 甚至更大的文件。
